# ADR-0005：检查时机与通知节流

- 状态：已接受（2025-08-24，grill-with-docs 访谈定稿；用户确认）

## 背景

托盘常驻可能数日不重启；系统通知弹太频会惹人烦，但“检测并提示”又是本功能核心。

## 决策

- **检查时机**三通道：
  1. 启动后延迟 ~30s 首查（不打扰启动序列）；
  2. 之后每 24h 自动查一次（config 记 `lastUpdateCheckAt`，重启也尊重冷却期）；
  3. 菜单「检查更新」随时手动触发，结果必有反馈。
- **系统通知节流**：config 记 `lastNotifiedVersion`，同一目标版本只弹一次系统通知；
  菜单常驻升级入口照常显示，直到升级完成或版本变化。
- 手动检查无新版本 → 弹通知“已是最新 x.y.z”（带当前版本号）。
- 所有检查/网络操作在独立 daemon 线程，任何失败静默记录日志，绝不影响托盘主流程。
- 不提供“关闭自动检查”开关（保持零配置；未来有需求再加）。

## 后果

- 常驻用户也能在一天内感知新版本；打扰上限为每版本一条通知。
- config 新增 3 个键：`lastUpdateCheckAt` / `lastNotifiedVersion` /
  `lastKnownLatestVersion`（菜单显示用缓存）。旧配置无需迁移（缺省即未检查）。
