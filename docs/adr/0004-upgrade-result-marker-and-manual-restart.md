# ADR-0004：升级结果由托盘直接感知；重启交由用户一键触发

- 状态：已接受（2025-08-24 定稿；同日随 ADR-0002 修订——静默执行后子进程归托盘
  直接管，原「marker 状态文件回传」方案废除）

## 背景

原可见终端方案中升级进程在托盘之外，退出码须经状态文件回传。静默执行（ADR-0002）
后托盘自己 spawn 升级命令，退出码直接可得，无需任何跨进程信号传递。
原则不变：**不强制升级、不强制重启**（与本应用“只管自己启动的进程”的克制一致）。

## 决策

- 执行升级的 daemon 线程 `wait()` 拿退出码：
  - `0` → 系统通知「升级完成，建议重启」；托盘自管进程在跑时菜单出现
    「重启以应用新版本」（复用现有 restart 动作），**不自动重启**；
  - 非 0 → 失败通知：原因摘要 + 完整手动命令（ADR-0002）；菜单保留升级项可重试。
- 升级进行中：菜单升级项置灰「升级中…」防重入；异常久（约 30 分钟）超时终止子进程，
  恢复菜单可用，状态回到「发现新版本」。
- `external` 外部启动态：不提供一键重启（外部进程不归托盘管），成功文案说明
  需自行重启外部实例。
- 升级成功后清除 lastKnownLatestVersion / lastNotifiedVersion 等缓存状态。

## 后果

- 无 marker 文件、无 watcher、无平台差异——比原方案少一整层机制。
- 升级子进程由托盘监管：意外退出也能感知并进入失败路径。
- 重启仍是用户动作，不打断进行中的会话。
