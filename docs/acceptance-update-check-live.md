# 更新检测功能：实机手动验收清单（v1.6.0）

与 `tests/test_integration_live.py` 同类的**人工验收清单**：自动化测试已用 mock 覆盖判定
逻辑（171 个单测），本清单验证真实托盘 GUI、真实网络与真实包管理器下的端到端行为。

- 验收环境：macOS / Windows 各过一遍；托盘正常运行（GUI 主循环不能在无头会话启动）
- 快捷准备：改动判定前先把 `~/.dsh-web-tray/config.json` 里 `lastUpdateCheckAt` 置 0、
  `lastNotifiedVersion`/`lastKnownLatestVersion` 置 ""，避免冷却/节流干扰
- 升级会真实改动本机 dsh 安装：npm 类可先 `npm install -g @deepseek-ai/dsh@<旧版>` 降级再验

## A. global（npm 全局）安装

- [ ] A1 启动检测：启动托盘约 30s 后自动检查；有新版 → 系统通知一条「发现新版本」，
      顶层菜单出现「🆕 升级到 x.y.z」（版本号 = 通知版本）
- [ ] A2 通知节流：再次手动「帮助 → 检查更新」→ **不再弹**系统通知（同版本只弹一次），
      菜单升级项仍在
- [ ] A3 已是最新：dsh 处于最新时手动检查 → 通知「当前已是最新版本 x.y.z」（带版本号）
- [ ] A4 静默升级：点「升级到 x.y.z」→ 无窗口弹出、菜单项变「🔄 升级中…」置灰；
      重复点击无二次执行
- [ ] A5 升级成功：通知「升级完成，建议重启」；dsh 在跑 → 菜单出现「🔄 重启以应用新版本」
- [ ] A6 一键重启：点重启项 → dsh 重启；`dsh --version` = 新版本号；重启项消失
- [ ] A7 升级日志：`~/.dsh-web-tray/logs/upgrade.log` 有完整 npm 输出
- [ ] A8 持久化：升级成功后重启托盘 → 不会重新弹同版本通知、菜单无残留升级项

## B. local（npx 本地）安装

- [ ] B1 检测与 A1 一致（registry latest 对比）
- [ ] B2 升级命令在配置的 dshDir 下执行（升级日志可见 cwd 生效），node_modules 内包版本更新

## C. pnpm（源码）安装

- [ ] C1 落后检测：源码仓库 reset 到旧提交 → 检查 → 通知「DSH 源码有更新：…落后 N 提交」，
      菜单出现升级项（不带版本号）
- [ ] C2 已最新：源码与远端一致 → 手动检查 → 通知为「当前已是最新」类文案
      （不显示假版本号「未知」）
- [ ] C3 静默升级：升级项点击 → git pull && pnpm install && pnpm run build 静默执行，
      输出落 upgrade.log；成功后通知 + 重启项语义同 A5/A6
- [ ] C4 detached HEAD：源码仓库 checkout 到分离头指针 → 检查 → 静默不提示

- [ ] D2 CLI `--check-update` 打印「未知，跳过判定」结论

## E. 边界场景

- [ ] E1 external 态（先在终端起一个 dsh web 再开托盘，青色图标）：检测/通知/升级入口正常；
      升级成功通知文案提示「自行重启外部实例」，**无**一键重启菜单项
- [ ] E2 断网：关网后手动「检查更新」→ 有明确失败反馈（不崩溃不卡死）；自动检查完全静默，
      托盘其余功能不受影响
- [ ] E3 镜像滞后：registry 配置为 npmmirror 且 latest < 本地版本（如本地 0.1.1-rc.2、
      镜像仍 0.1.0）→ **不**提示升级；CLI 打印「已是最新版本」
- [ ] E4 升级失败路径：临时把 dshDir 改成无权限/不存在目录再升级 → 失败通知含原因摘要 +
      完整手动命令；菜单升级项保留可重试；恢复目录后重试成功
- [ ] E5 检查冷却：刚自动检查完（<24h）重启托盘 → 不再立即检查（tray.log 无第二次
      「开始更新检查」），尊重 lastUpdateCheckAt
